## 背景

### 專題定位與動機

本專題希望利用電腦視覺與深度學習，從影片取得運動員的身體姿態及船槳相關資訊，進一步分析划槳動作。這類方法不需要在運動員身上額外安裝感測器，較方便保留一般訓練或比賽影片進行分析。

學長姊的既有系統主要以**室內划船機、單人划槳影片**為對象。後續若要延伸到**戶外龍舟、多人同時划槳**，將面臨人員與船槳互相遮擋、拍攝角度、光照變化、多人對應等問題。

> 備註：戶外多人分析目前列為可能的延伸方向，不等於功能已完成，也不代表最終場景已正式定案。

### 名詞解釋

| 名詞 | 說明 |
|---|---|
| 重現（Reproduction） | 在可比的資料、設定與環境下，重新執行既有方法，確認能否得到相近結果。 |
| 偽標籤（Pseudo-label） | 先由模型自動產生標註，再用於後續訓練或修正。 |
| 2D 姿態估計 | 在影像平面中預測人體關鍵點的位置。 |
| 3D 姿態估計 | 推估人體關鍵點在三維空間中的位置或相對結構。 |
| 動作指標 | 從關鍵點、關節角度或船槳資訊計算出的可比較數值。 |

## 系統概述

目前已知的學長姊系統可拆成兩條流程。以下描述的是**舊系統的技術架構**，不是本組已完成的重現成果。

### 1. 船槳偵測：YOLO 分支

**大致流程：**影片／影格 → 船槳偵測 → 船槳方向修正 → 船槳相關資訊

- **RF-DETR**：用來自動產生船槳偽標籤，協助建立 YOLO 訓練資料。
- **YOLOv11s**：用來偵測影片中的船槳位置；既有資料提到輸入尺寸為 640 × 640。
- **方向修正**：在偵測框內利用亮度資訊尋找線段，修正船槳方向的估計。

要注意：RF-DETR 產生偽標籤主要屬於資料準備／訓練流程，不代表正式推論時每張影格都需要先執行 RF-DETR。

### 2. 人體姿態分析：骨架分支

**大致流程**：影片／影格 → 人體偵測 → 2D 姿態估計 → 3D 姿態推估 → 動作指標

- **Faster R-CNN**：偵測畫面中的人員。舊流程曾以偵測框面積與接近畫面中心等條件篩選主要運動員。
- **ViTPose（MMPose）**：取得人體 2D 關鍵點。
- **TCPFormer**：利用時序資訊推估 3D 骨架，減少單張影格在遮擋或抖動下的不穩定。
- **動作分析**：根據關鍵點計算肘部角度、前臂投影等量化指標。

### 3. 兩條分支後續如何整合

預期可將船槳資訊與人體骨架資訊對齊，用於解讀划槳動作。但目前還需要釐清兩條分支的輸入輸出格式、時間同步方式，以及同一位運動員與船槳的對應關係。

因此，**分支成功重現**與**完整系統成功整合**應視為兩個不同階段，不宜混在一起認定已完成。

## 問題彙整

### 技術與實作問題

1. **程式是否能完整執行？** 原始程式、相依套件、模型權重與測試資料是否齊全，版本是否相容？
2. **結果是否真的重現？** 除了程式能執行，也需要有輸出影像／影片與原始結果的可比較證據。
3. **輸入資料是否相符？** 舊系統主要使用室內單人影片；新場景在視角、光照與遮擋上可能不同，不能直接假設性能相同。
4. **兩條分支如何串接？** 需要確認時間軸、座標系統及人員與船槳的配對方式。
5. **評估方式是什麼？** 船槳偵測、骨架估計與動作分析需要各自的評估指標，不能只用「看起來可以跑」作為驗收。

### 專題定位與需求問題

1. 正式使用情境要以室內訓練、戶外龍舟，還是兩者比較為主？
2. 最終系統要協助哪一類使用者？例如教練、運動員或研究人員；實際 User Need 尚需對應本次龍舟方向確認。
3. 哪些動作指標最有意義？目前已知舊系統有肘角與前臂投影，但後續是否擴充同步性、一致性等指標尚未定案。
4. 專題的研究貢獻是模型改良、跨場景適應、多人追蹤，還是完整分析工具？仍需依重現結果與可用資料評估。

## 建議與下一階段工作

1. **先完成兩條分支的重現驗證**：各自提供環境版本、執行指令、測試影片、輸出結果及失敗紀錄。

3. **整理輸入／輸出介面**：盤點 YOLO 與骨架分支的資料格式，評估後續整合所需工作。
4. **確認具體使用情境和驗收標準**：先回答系統要解決誰的什麼問題，再決定需要哪些動作指標。
5. **再決定研究貢獻**：重現結果與資料限制明確後，評估戶外多人、遮擋處理、動作量化或其他延伸方向的可行性。
